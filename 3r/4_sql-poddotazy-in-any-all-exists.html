Patří hodnota do množiny? IN, ANY, ALL a EXISTS.

Zatím jsme ve WHERE porovnávali hodnotu s jednou jinou hodnotou: grade = 1, class_id = 2. Teď ji budeme porovnávat s celou množinou hodnot – se seznamem nebo s výsledkem jiného dotazu.

Kde jsme: v kapitole o JOIN jsme hledali žáky bez známky pomocí LEFT JOIN … IS NULL a slíbili si, že totéž umí i poddotaz. Dnes ho poznáme – a s ním operátory, které se s poddotazy používají nejčastěji.
01 • LOGICKÉ OPERÁTORY

Co už známe a co přibude

Logický operátor vrací pravdivostní hodnotu. Ve WHERE projde řádek do výsledku jen tehdy, když je podmínka TRUE. V SQL ale existuje i třetí hodnota – UNKNOWN (neznámo), která vzniká při práci s NULL. Uvidíme, že je to dnes velmi důležité.

03 • PODDOTAZ

SELECT uvnitř SELECTu

Poddotaz (subquery, vnořený dotaz) je celý SELECT zapsaný v závorkách uvnitř jiného dotazu. Databáze nejdřív zjistí jeho výsledek a ten pak použije vnější dotaz – jako by tam byl napsaný ručně.

Úloha: kteří žáci mají známku z matematiky?

SELECT id, name
FROM students
WHERE id IN (
    SELECT student_id          -- poddotaz
    FROM grades
    WHERE subject_id = 1
);
1

Vnitřní dotaz

Vrátí sloupec student_id známek z MAT: 1, 2, 3.

2

Dosazení

Vnější dotaz se chová, jako by bylo napsáno WHERE id IN (1, 2, 3).

3

Výsledek

Novák, Svobodová, Dvořák.

Tři tvary výsledku poddotazu

TvarPříkladKde se použije
Skalární
1 řádek × 1 sloupec		(SELECT id FROM subjects WHERE code = 'MAT') → 1místo jedné hodnoty: subject_id = (…)
Sloupcový
N řádků × 1 sloupec		(SELECT grade FROM grades WHERE subject_id = 1) → 1, 3, 4IN, ANY, SOME, ALL
Tabulkový
N řádků × M sloupců		(SELECT * FROM grades WHERE …)EXISTS (na sloupcích nezáleží), FROM (…) AS t
Nekorelovaný

Nezávisí na vnějším dotazu

Dá se spustit samostatně. Logicky se vyhodnotí jednou a výsledek se použije pro všechny řádky. Příklad výše.

Korelovaný

Odkazuje na vnější řádek

Obsahuje sloupec vnějšího dotazu, např. g.student_id = s.id. Logicky se vyhodnotí pro každý řádek vnějšího dotazu znovu. Typické pro EXISTS.

Rada: poddotaz si nejdřív spusť samostatně (bez vnějšího dotazu). Uvidíš přesně tu množinu, se kterou bude IN, ANY nebo ALL porovnávat.
04 • IN A NOT IN

IN: je hodnota v seznamu?

x IN (a, b, c) je zkratka pro x = a OR x = b OR x = c. Množinu můžeme zapsat ručně jako seznam, nebo ji získat poddotazem.

Seznam hodnot

SELECT id, code
FROM subjects
WHERE code IN ('MAT', 'DAT');

-- totéž bez IN:
-- WHERE code = 'MAT' OR code = 'DAT'

Výsledek – 2 řádky

idcode
1MAT
3DAT

Poddotaz

-- předměty, ze kterých existuje známka
SELECT code
FROM subjects
WHERE id IN (SELECT subject_id FROM grades);

Výsledek – 3 řádky

code
MAT
CJL
DAT

Poddotaz vrátí 1, 3, 1, 2, 1, 3 – duplicity nevadí, IN se ptá jen „je tam?“.

Poddotaz s JOINem uvnitř

V poddotazu může být cokoli, co už umíme – i JOIN. Hlavně musí vracet jeden sloupec.

-- žáci se známkou z DAT nebo CJL
SELECT name
FROM students
WHERE id IN (
    SELECT g.student_id
    FROM grades AS g
    JOIN subjects AS sub ON sub.id = g.subject_id
    WHERE sub.code IN ('DAT', 'CJL')
);

Výsledek – 3 řádky

Svobodová
Malý

Novák má známku z DAT, Svobodová z CJL, Malý z DAT.

NOT IN: není v seznamu

-- žáci, kteří nemají žádnou známku
SELECT id, name
FROM students
WHERE id NOT IN (SELECT student_id FROM grades);

Stejný výsledek jako LEFT JOIN … WHERE g.id IS NULL z minulé kapitoly – jen čitelněji.

Funguje to jen díky tomu, že grades.student_id je NOT NULL. Kdyby poddotaz pro NOT IN vrátil jediné NULL, výsledek by byl prázdný. Proč? To je další kapitola.
05 • PAST JMÉNEM NULL

Proč NOT IN někdy nevrátí nic

Úloha: Které třídy nemají žádného žáka? Správná odpověď je 3.C. Zkusme to přes NOT IN:

SELECT id, name
FROM classes
WHERE id NOT IN (SELECT class_id FROM students);

Výsledek – 0 řádků 😮

idname
(prázdný výsledek)

Co se stalo u třídy 3.C?

Poddotaz vrátil 1, 1, 2, 2, NULL (Malý nemá třídu). NOT IN se rozepíše na řadu nerovností spojených AND:

porovnánívýsledek
3 <> 1TRUE
3 <> 1TRUE
3 <> 2TRUE
3 <> 2TRUE
3 <> NULLUNKNOWN
AND všechUNKNOWN

Nevíme, zda se 3 nerovná neznámé hodnotě. Celek je proto UNKNOWN – a WHERE propouští jen TRUE.

Trojhodnotová logika u IN v kostce

VýrazVýsledekProč
3 IN (1, 2)FALSE3 se nerovná žádné hodnotě.
1 IN (1, NULL)TRUEShoda s 1 stačí, NULL už nic nezmění.
3 IN (1, NULL)UNKNOWNShoda nenalezena, ale neznámá hodnota by 3 být mohla.
3 NOT IN (1, NULL)UNKNOWNNOT z UNKNOWN je pořád UNKNOWN.
NULL IN (1, 2)UNKNOWNNeznámou hodnotu nelze porovnat.

Dvě správná řešení

1 • vyřadit NULL 
SELECT id, name
FROM classes
WHERE id NOT IN (
    SELECT class_id
    FROM students
    WHERE class_id IS NOT NULL
);
2 • NOT EXISTS (doporučeno) 
SELECT c.id, c.name
FROM classes AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM students AS s
    WHERE s.class_id = c.id
);

Oba vrátí – 1 řádek

idname
33.C
Pravidlo: u NOT IN (poddotaz) se vždy zeptej: „Může poddotaz vrátit NULL?“ Pokud ano (sloupec není NOT NULL), přidej WHERE … IS NOT NULL, nebo použij NOT EXISTS.
06 • ANY / SOME

ANY: platí aspoň pro jednu hodnotu?

x <operátor> ANY (poddotaz) je TRUE, když porovnání platí alespoň s jednou hodnotou z poddotazu. SOME je jen jiný název pro totéž – ANY a SOME jsou zaměnitelné.

Známky lepší (menší číslo) než aspoň jedna známka z MAT

SELECT s.name, sub.code, g.grade
FROM grades AS g
JOIN students AS s   ON s.id = g.student_id
JOIN subjects AS sub ON sub.id = g.subject_id
WHERE g.grade < ANY (
    SELECT grade FROM grades WHERE subject_id = 1
);   -- známky z MAT: 1, 3, 4

Výsledek – 5 řádků

namecodegradeproč
NovákMAT11 < 3 ✓
NovákDAT11 < 3 ✓
SvobodováMAT33 < 4 ✓
SvobodováCJL11 < 3 ✓
MalýDAT22 < 3 ✓

Chybí jen Dvořákova čtyřka: 4 není menší než 1, 3 ani 4.

Jak ANY „přemýšlí“

x < ANY (1, 3, 4) se rozepíše na x < 1 OR x < 3 OR x < 4. Stačí jedna pravda. Prakticky to znamená x < největší hodnota.

ZápisSlovyStejně jako
x = ANY (…)x se rovná aspoň jedné hodnotěx IN (…)
x < ANY (…)x je menší než aspoň jedna hodnotax < největší hodnota
x > ANY (…)x je větší než aspoň jedna hodnotax > nejmenší hodnota
x <> ANY (…)x se liší aspoň od jedné hodnotytéměř vždy TRUE – pozor, viz níže

= ANY je totéž co IN

-- spolužáci Nováka (ze stejné třídy)
SELECT name
FROM students
WHERE class_id = ANY (
        SELECT class_id
        FROM students
        WHERE name = 'Novák'
      )
  AND name <> 'Novák';

Výsledek: Svobodová

Past: <> ANY není „žádný“

-- chtěli jsme žáky BEZ známky…
SELECT name
FROM students
WHERE id <> ANY (SELECT student_id FROM grades);
-- …a dostali jsme VŠECH 5 žáků

Každé id se liší aspoň od jednoho student_id v seznamu. Anglické „not equal to any“ znamená v běžné řeči „žádnému“, v SQL ale ne! Pro „žádnému“ použij NOT IN nebo <> ALL.

MySQL / MariaDB: za ANY, SOME i ALL musí následovat poddotaz. Ručně zapsaný seznam grade = ANY (1, 2) skončí syntaktickou chybou – pro seznam hodnot použij IN.
07 • ALL

ALL: platí pro všechny hodnoty?

x <operátor> ALL (poddotaz) je TRUE, když porovnání platí se všemi hodnotami z poddotazu. Rozepisuje se pomocí AND.

Nejlepší známky v celé škole

SELECT s.name, sub.code, g.grade
FROM grades AS g
JOIN students AS s   ON s.id = g.student_id
JOIN subjects AS sub ON sub.id = g.subject_id
WHERE g.grade <= ALL (SELECT grade FROM grades);

Výsledek – 3 řádky

namecodegrade
NovákMAT1
NovákDAT1
SvobodováCJL1

Jednička je ≤ všem známkám (1, 1, 3, 1, 4, 2). Dvojka ne – není ≤ 1.

Jak ALL „přemýšlí“

x > ALL (1, 3, 4) se rozepíše na x > 1 AND x > 3 AND x > 4. Musí platit všechno. Prakticky to znamená x > největší hodnota.

ZápisSlovyStejně jako
x > ALL (…)x je větší než všechny hodnotyx > největší hodnota
x < ALL (…)x je menší než všechny hodnotyx < nejmenší hodnota
x <> ALL (…)x se liší od všech hodnot, tj. nerovná se žádnéx NOT IN (…)
x = ALL (…)všechny hodnoty se rovnají xmnožina obsahuje jen x (nebo je prázdná!)

Kombinace s další podmínkou

-- nejlepší známka z matematiky
SELECT s.name, g.grade
FROM grades AS g
JOIN students AS s ON s.id = g.student_id
WHERE g.subject_id = 1
  AND g.grade <= ALL (
        SELECT grade FROM grades WHERE subject_id = 1
      );

Výsledek: Novák, 1

Horší než všechny z DAT

SELECT s.name, g.grade
FROM grades AS g
JOIN students AS s ON s.id = g.student_id
WHERE g.grade > ALL (
        SELECT grade FROM grades
        WHERE subject_id = 3      -- DAT: 1, 2
      );

Výsledek: Svobodová 3, Dvořák 4

Dvě zvláštnosti ALL, které musíš znát

prázdný poddotaz

ALL nad ničím = TRUE

SELECT COUNT(*) FROM grades
WHERE grade < ALL (
  SELECT grade FROM grades
  WHERE subject_id = 4     -- ANJ: žádné
);
-- 6  (všechny známky!)

„Všechny známky z ANJ jsou horší“ – žádné nejsou, takže nelze najít protipříklad. Tvrzení o prázdné množině je vždy pravdivé. Naopak ANY nad prázdnou množinou je vždy FALSE (vrátil by 0).

NULL v poddotazu

Jedno NULL zablokuje vše

SELECT id, name FROM classes
WHERE id > ALL (SELECT class_id FROM students);
-- 0 řádků

-- bez NULL:
WHERE id > ALL (SELECT class_id FROM students
                WHERE class_id IS NOT NULL);
-- 3.C

U 3.C: 3 > 1 AND … AND 3 > NULL = UNKNOWN. Stejná past jako u NOT IN – <> ALL je přece totéž co NOT IN.

09 • EXISTS
EXISTS: vrátí poddotaz aspoň jeden řádek?


EXISTS (poddotaz) nic neporovnává. Ptá se jen, zda je výsledek poddotazu neprázdný. Vrací vždy TRUE, nebo FALSE – nikdy UNKNOWN, a proto mu NULL nevadí.






Žáci, kteří mají aspoň jednu známku


SELECT s.id, s.name
FROM students AS s
WHERE EXISTS (
    SELECT 1
    FROM grades AS g
    WHERE g.student_id = s.id   -- korelace
);


SELECT 1 je zvyk: na tom, co poddotaz vybírá, nezáleží – EXISTS zajímá jen, zda něco vrátí. Stejně dobře funguje SELECT *.






Vyhodnocení řádek po řádku

2Svobodová… WHERE g.student_id = 22TRUE


3Dvořák… WHERE g.student_id = 31TRUE


4Černá… WHERE g.student_id = 40FALSE


5Malý… WHERE g.student_id = 51TRUE




Korelovaný poddotaz: pro každého žáka se „dosadí“ jeho s.id. Výsledek: Novák, Svobodová, Dvořák, Malý.











NOT EXISTS: hledání chybějících


-- předměty, ze kterých nikdo nemá známku
SELECT sub.code
FROM subjects AS sub
WHERE NOT EXISTS (
    SELECT 1
    FROM grades AS g
    WHERE g.subject_id = sub.id
);
-- ANJ






Podmínka může být libovolně složitá


-- třídy, kde má někdo jedničku
SELECT c.name
FROM classes AS c
WHERE EXISTS (
    SELECT 1
    FROM students AS s
    JOIN grades AS g ON g.student_id = s.id
    WHERE s.class_id = c.id
      AND g.grade = 1
);
-- 2.A







EXISTS + ALL: „všechny“ jen tam, kde něco je


Úloha: žáci, kteří mají ze všech předmětů jedničku. První nápad:




Chybně

SELECT s.name
FROM students AS s
WHERE 1 = ALL (
    SELECT grade FROM grades AS g
    WHERE g.student_id = s.id
);
-- Novák, Černá  ← Černá nemá žádnou známku!


Správně

SELECT s.name
FROM students AS s
WHERE EXISTS (SELECT 1 FROM grades AS g
              WHERE g.student_id = s.id)
  AND 1 = ALL (SELECT grade FROM grades AS g
               WHERE g.student_id = s.id);
-- Novák




Pro Černou vrátí poddotaz prázdnou množinu a ALL nad prázdnou množinou je TRUE. Kdykoli píšeš „všechny“, zeptej se: „A co když tam není nic?“ Pokud to nechceš, přidej EXISTS.








10 • SROVNÁNÍ
IN, EXISTS, nebo JOIN?


Mnoho úloh jde vyřešit více způsoby. Rozdíl je hlavně v tom, co dotaz vrací a jak se chová k NULL.




JOIN

SELECT s.name
FROM students s
JOIN grades g
  ON g.student_id = s.id
WHERE g.grade = 1;
-- Novák, Novák, Svobodová


IN

SELECT s.name
FROM students s
WHERE s.id IN (
  SELECT student_id
  FROM grades
  WHERE grade = 1);
-- Novák, Svobodová


EXISTS

SELECT s.name
FROM students s
WHERE EXISTS (
  SELECT 1 FROM grades g
  WHERE g.student_id = s.id
    AND g.grade = 1);
-- Novák, Svobodová




JOIN násobí řádky (Novák má dvě jedničky, proto je tam dvakrát – znáš z minulé kapitoly). IN a EXISTS jen filtrují: každý žák projde nejvýše jednou. Když chceš jen „kteří žáci…“, je poddotaz přirozenější; když potřebuješ i sloupce z druhé tabulky (předmět, známku), použij JOIN.




Tahák ekvivalencí




ZápisTotéž jakoPozor


x IN (poddotaz)x = ANY (poddotaz)—


x NOT IN (poddotaz)x <> ALL (poddotaz)NULL v poddotazu → nic


x > ANY (poddotaz)x > (SELECT MIN(…) …)liší se u prázdné množiny a NULL


x > ALL (poddotaz)x > (SELECT MAX(…) …)prázdná množina: ALL → TRUE, MAX → NULL → nic


NOT IN / LEFT JOIN … IS NULLNOT EXISTSNOT EXISTS je odolné vůči NULL








IN
Krátké seznamy hodnot a jednoduché „je v množině?“ s nekorelovaným poddotazem.


EXISTS / NOT EXISTS
„Má k sobě nějaký záznam?“ a hlavně negace – je bezpečná i při NULL.


ANY / ALL
Porovnání < > <= >= s celou množinou: „lepší než všechny“, „horší než aspoň jeden“.




A výkon? Moderní MySQL i MariaDB převádějí IN a EXISTS interně na podobné plány (semi-join), takže u běžných dotazů nemusíš volit podle rychlosti. Vybírej podle čitelnosti a správnosti.








11 • NA CO POZOR
Časté chyby a jak je poznat




Poddotaz vrací více řádků


WHERE id = (SELECT student_id FROM grades
            WHERE subject_id = 1);


ERROR 1242: Subquery returns more than 1 row. Operátor = čeká jednu hodnotu. Použij IN nebo = ANY.


Poddotaz vrací více sloupců


WHERE id IN (SELECT student_id, grade
             FROM grades);


ERROR 1241: Operand should contain 1 column(s). Pro IN, ANY i ALL musí poddotaz vracet jeden sloupec.


NOT IN a NULL
Jediné NULL ve výsledku poddotazu = prázdný výsledek celého dotazu. Bez chybové hlášky! Proto je tak zrádné.


ALL nad prázdnou množinou
Je vždy TRUE. „Všechny známky jsou 1“ splní i žák bez známek. Doplň EXISTS.


<> ANY místo „žádný“
Je TRUE téměř vždy. Pro „nerovná se žádné“ piš NOT IN nebo <> ALL.


LIMIT v poddotazu pro IN/ANY/ALL


WHERE id IN (SELECT student_id FROM grades
             ORDER BY grade LIMIT 3);


MySQL i MariaDB odpoví ERROR 1235: … doesn't yet support 'LIMIT & IN/ALL/ANY/SOME subquery'. Řešení: obalit poddotaz do odvozené tabulky FROM (… LIMIT 3) AS t.


ANY se seznamem hodnot
grade = ANY (1, 2) v MySQL/MariaDB neprojde. ANY/ALL vyžadují poddotaz, seznam patří do IN.


Zapomenutá korelace
WHERE EXISTS (SELECT 1 FROM grades) bez g.student_id = s.id je TRUE pro všechny řádky – tabulka grades přece není prázdná.










12 • PROCVIČ SI
Úlohy nad databází školy


Nejdřív zkus napsat dotaz sám, pak rozbal řešení. Všechna řešení jsou ověřená na ukázkových datech.


1. Žáci ze třídy 2.A – pomocí IN a poddotazu do tabulky classes (bez JOIN).


SELECT name
FROM students
WHERE class_id IN (SELECT id FROM classes WHERE name = '2.A');


Výsledek: Novák, Svobodová


2. Žáci, kteří nemají známku z matematiky (kód MAT).


SELECT name
FROM students
WHERE id NOT IN (
    SELECT student_id FROM grades
    WHERE subject_id = (SELECT id FROM subjects WHERE code = 'MAT')
);


Výsledek: Černá, Malý


NOT IN je tu bezpečné: grades.student_id je NOT NULL. Všimni si i skalárního poddotazu (SELECT id … 'MAT'), který vrací jedinou hodnotu, proto stačí =.


3. Známky, které jsou horší než všechny známky z databází (DAT). Vypiš jméno, předmět a známku.


SELECT s.name, sub.code, g.grade
FROM grades AS g
JOIN students AS s   ON s.id = g.student_id
JOIN subjects AS sub ON sub.id = g.subject_id
WHERE g.grade > ALL (
    SELECT grade FROM grades
    WHERE subject_id = (SELECT id FROM subjects WHERE code = 'DAT')
);


Výsledek: Svobodová MAT 3, Dvořák MAT 4


4. Třídy, ve kterých má aspoň jeden žák známku 1.


SELECT c.name
FROM classes AS c
WHERE EXISTS (
    SELECT 1
    FROM students AS s
    JOIN grades AS g ON g.student_id = s.id
    WHERE s.class_id = c.id AND g.grade = 1
);


Výsledek: 2.A


5. Které třídy nemají žádného žáka? Napiš dvě správné varianty.


-- a) NOT EXISTS
SELECT c.name FROM classes AS c
WHERE NOT EXISTS (SELECT 1 FROM students AS s WHERE s.class_id = c.id);

-- b) NOT IN s vyřazením NULL
SELECT name FROM classes
WHERE id NOT IN (SELECT class_id FROM students WHERE class_id IS NOT NULL);


Výsledek: 3.C


6. Žáci, kteří mají aspoň jednu známku a všechny jejich známky jsou lepší než 3.


SELECT s.name
FROM students AS s
WHERE EXISTS (SELECT 1 FROM grades AS g WHERE g.student_id = s.id)
  AND 3 > ALL (SELECT grade FROM grades AS g WHERE g.student_id = s.id);


Výsledek: Novák, Malý


Bez EXISTS by ve výsledku byla i Černá (ALL nad prázdnou množinou).


7. Předměty, ze kterých existuje známka a nikdo z nich nedostal horší známku než 2.


SELECT sub.code
FROM subjects AS sub
WHERE EXISTS (SELECT 1 FROM grades AS g WHERE g.subject_id = sub.id)
  AND 2 >= ALL (SELECT grade FROM grades AS g WHERE g.subject_id = sub.id);


Výsledek: CJL, DAT


8. Proč dotaz SELECT name FROM students WHERE id <> ANY (SELECT student_id FROM grades) vrátí všechny žáky? Oprav ho, aby vrátil žáky bez známky.


<> ANY je TRUE, když se id liší aspoň od jedné hodnoty – a to platí pro každého. Správně:


SELECT name FROM students
WHERE id <> ALL (SELECT student_id FROM grades);   -- = NOT IN


Výsledek: Černá








13 • SHRNUTÍ
Co si odnést




① Poddotaz
SELECT v závorkách. Pro IN/ANY/ALL vrací jeden sloupec, pro EXISTS na sloupcích nezáleží.


② IN
„Rovná se některé hodnotě?“ Seznam i poddotaz. IN = = ANY.


③ ANY / SOME
„Platí aspoň pro jednu?“ → spojení přes OR. Prázdná množina = FALSE.


④ ALL
„Platí pro všechny?“ → spojení přes AND. Prázdná množina = TRUE!


⑤ EXISTS
„Vrátí poddotaz aspoň řádek?“ Jen TRUE/FALSE, NULL mu nevadí. Typicky korelovaný.


⑥ NULL
NOT IN a ALL s NULL v poddotazu dávají UNKNOWN → prázdný výsledek. Pro negace preferuj NOT EXISTS.






Tři otázky před každým poddotazem:


1. Co přesně poddotaz vrací? (spusť ho samostatně) 2. Může v tom být NULL? 3. Co když bude prázdný? – Odpovědi rozhodují mezi IN, ALL a EXISTS.
