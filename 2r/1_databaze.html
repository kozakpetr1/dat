Informatika • Databáze

Proč vůbec vznikly databáze?

Protože ukládat data do souborů nestačí. Jakmile dat přibývá, potřebujeme je rychle hledat, měnit, sdílet, chránit a udržet konzistentní.

datastrukturadotazyvíce uživatelůbezpečnost
Myšlenka: databáze není jen „místo, kam se uloží tabulka“. Je to způsob, jak data organizovat a pracovat s nimi jako s celkem.
01 • PROBLÉM

Od souborů k databázi

Představ si školu, e-shop nebo banku. Informace nejsou izolované — souvisejí spolu a současně s nimi pracuje mnoho operací i uživatelů.

📄

Jen soubory

Data mohou být rozházená v CSV, Excelu nebo textových souborech. Stejná informace se často opakuje.

🔎

Potřebujeme dotazy

„Najdi všechny žáky 3.KC, kteří mají praxi v Praze.“ Ruční hledání není řešení pro tisíce záznamů.

🔐

Potřebujeme pravidla

Kdo smí data měnit? Co když dva lidé upravují stejný záznam? Co při výpadku během zápisu?

Databáze řeší problém organizace + dostupnosti + konzistence + bezpečnosti dat.

02 • MODELY

Databázový model = způsob, jak data uspořádáme

Databázový model určuje, jak jsou data strukturována, jak mezi sebou souvisejí a jak s nimi lze pracovat.

Klasické / relační

Relační model

Data jsou v tabulkách. Tabulky propojují klíče a vztahy. Pracujeme typicky pomocí SQL.

Příklad: students ↔ classes ↔ internships

NoSQL

Dokumentový model

Data jsou uložena jako dokumenty, často podobné JSON. Struktura dokumentů může být flexibilnější.

Příklad: { name: "Jan", skills: [...] }

NoSQL

Klíč–hodnota

Velmi jednoduchý princip: ke klíči patří hodnota. Vhodné například pro cache nebo rychlé lookupy.

Příklad: user:42 → "Petr"

NoSQL

Grafový model

Data tvoří uzly a hrany. Hodí se tam, kde jsou zásadní vztahy mezi objekty.

Příklad: osoby → pracují_v → firmách

Pozor na pojmy: SQL/NoSQL není totéž co „typ databáze“. SQL je jazyk a relační databáze je model. NoSQL označuje skupinu nerelačních přístupů.
03 • ZÁKLADNÍ POJEM

DBS = DB + DBMS

Tady se často pletou tři pojmy. Zapamatuj si rozdíl mezi daty, databází a systémem, který databázi spravuje.

DBDatabase
databáze
+
DBMSDatabase Management System
software pro správu
=
DBSDatabase System
databázový systém

DB

Samotná organizovaná data — například tabulky, indexy, vazby a uložené informace.

DBMS

Programové vybavení, které databázi vytváří, spravuje a zpřístupňuje aplikacím a uživatelům.

DBS

Celé řešení: databáze + DBMS (v praxi také lidé, aplikace, hardware a další části prostředí).

04 • DBMS

Co vlastně DBMS dělá?

01

Ukládá a organizuje

Spravuje data, tabulky, indexy, metadata a struktury databáze.

02

Vyhledává

Vyhodnocuje dotazy a používá například indexy, aby data našel efektivně.

03

Hlídá pravidla

Kontroluje datové typy, klíče, omezení a integritu dat.

04

Řeší více uživatelů

Řídí souběžné operace a transakce, aby nedocházelo k nekonzistentním stavům.

05

Zajišťuje bezpečnost

Účty, role a oprávnění určují, kdo může data číst nebo měnit.

06

Zvládá výpadky

Mechanismy transakcí, logování a obnovy pomáhají zachovat konzistenci.

07

Komunikuje s aplikací

Aplikace posílá DBMS požadavky — například SQL dotazy — a získává výsledky.

08

Optimalizuje práci

DBMS rozhoduje, jak dotaz provést co nejefektivněji.

05 • CO POTKÁŠ V PRAXI

Ne každý databázový systém funguje stejně

Některé systémy jsou plnohodnotné serverové DBMS, jiné jsou zabudované přímo do aplikace a další používají jiný databázový model.

SystémModelJak fungujeTypické použití
MySQLrelační / SQLServerový DBMSwebové aplikace, informační systémy
MariaDBrelační / SQLServerový DBMSweb, školy, firmy, aplikace
PostgreSQLrelační / SQLServerový DBMSrobustní aplikace, analytika, GIS
SQLiterelační / SQLembedded — knihovna přímo v aplikacimobilní/desktop aplikace, malé lokální databáze
MongoDBdokumentový / NoSQLServerový databázový systémaplikace s dokumentovými daty, flexibilní schéma
Redisklíč–hodnota / NoSQLserver, primárně in-memorycache, rychlé datové struktury, fronty
MySQL ≈ MariaDB: oba jsou klasické serverové relační DBMS a používají SQL. Nejde tedy o „databázi“ jako takovou, ale o software, který databáze spravuje.
SQLite je jiný způsob nasazení: nemá typický samostatný databázový server. Databázový engine je součástí aplikace a databáze bývá v jednom souboru.
06 • ORIENTACE

Jak si to všechno poskládat?

1. Co ukládám?

Rozhoduje charakter dat: tabulková data, dokumenty, vztahy, klíč–hodnota…

2. Jak s nimi pracuji?

Potřebuji SQL? Složité vazby? Rychlé čtení? Flexibilní strukturu?

3. Kde systém poběží?

Lokálně v aplikaci? Na serveru? Pro jednoho uživatele nebo tisíce současně?

Praktická mapa: Školní informační systém → často relační DBMS (např. MariaDB/PostgreSQL). Mobilní aplikace s lokálními daty → často SQLite. Aplikace pracující s dokumenty → může použít MongoDB. Rychlá cache → může využít Redis.
07 • CO SI ODNÉST

Šest vět, které bys měl umět vysvětlit

① Proč databáze?

Protože potřebujeme efektivně a bezpečně spravovat větší množství souvisejících dat.

② Co je databázový model?

Pravidla, podle kterých jsou data strukturována a propojena.

③ Co je DB?

Organizovaná kolekce dat a souvisejících struktur.

④ Co je DBMS?

Software, který databázi spravuje a poskytuje k ní rozhraní.

⑤ Co znamená DBS?

DBS = DB + DBMS — databáze a systém pro její správu.

⑥ Proč existuje tolik systémů?

Protože různé aplikace mají různé požadavky na strukturu, výkon, škálování a způsob práce s daty.
