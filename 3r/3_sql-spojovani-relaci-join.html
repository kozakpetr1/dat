Data jsou rozdělená. JOIN je skládá zpět.

Dobře navržená databáze ukládá každou informaci jen jednou – žáky do jedné tabulky, třídy do druhé, známky do třetí. Když pak chceme vidět „žák, jeho třída a jeho známky“ v jednom výsledku, musíme tabulky spojit.

INNER JOINLEFT JOINRIGHT JOINCROSS JOINONIS NULL
Kde jsme: v minulé kapitole jsme seskupovali a počítali souhrny – ale vše bylo v jediné tabulce grades. Teď data rozdělíme tak, jak to dělá skutečná databáze, a naučíme se je zase spojovat. Na konci obě témata propojíme.
01 • PROČ JOIN

Proč nemít všechno v jedné tabulce?

V minulé kapitole měla tabulka u každé známky napsané jméno žáka i třídu. To je pohodlné na čtení, ale nepraktické na údržbu.

📝

Opakování

„Novák, 2.A“ je zapsáno u každé jeho známky. Při 40 známkách 40×.

🔀

Nekonzistence

Když Novák přestoupí do 2.B, musíme opravit všechny řádky. Zapomeneme-li jeden, je v databázi ve dvou třídách najednou.

🕳️

Nelze uložit

Novou třídu bez žáků nebo nového žáka bez známek nemáme kam zapsat.

Proto data rozdělíme do více tabulek (normalizace – znáš z návrhu databáze) a propojíme je klíči: cizí klíč (FK) v jedné tabulce ukazuje na primární klíč (PK) v jiné.

Jak číst diagram: jedna třída má N žáků (students.class_id → classes.id), jeden žák má N známek (grades.student_id → students.id) a k jednomu předmětu patří N známek. Tabulka grades zároveň realizuje vztah M:N mezi žáky a předměty.

Skript pro vytvoření databáze – zkopíruj a vyzkoušej
CREATE TABLE classes (
  id   INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(10) NOT NULL
);

CREATE TABLE students (
  id       INT AUTO_INCREMENT PRIMARY KEY,
  name     VARCHAR(50) NOT NULL,
  class_id INT NULL,
  FOREIGN KEY (class_id) REFERENCES classes(id)
);

CREATE TABLE subjects (
  id   INT AUTO_INCREMENT PRIMARY KEY,
  code CHAR(3)     NOT NULL,
  name VARCHAR(50) NOT NULL
);

CREATE TABLE grades (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  student_id INT NOT NULL,
  subject_id INT NOT NULL,
  grade      TINYINT NOT NULL,
  FOREIGN KEY (student_id) REFERENCES students(id),
  FOREIGN KEY (subject_id) REFERENCES subjects(id)
);

Každý s každým – a pak jen ty, kdo k sobě patří

Nejspolehlivější představa, jak JOIN funguje: databáze (myšlenkově) zkusí každý řádek první tabulky s každým řádkem druhé a ponechá jen dvojice, které splní podmínku spojení.

Pozn.: skutečná databáze 15 dvojic opravdu nevytváří – použije indexy a najde páry chytřeji. Výsledek je ale vždy stejný, jako kdyby to udělala. Tahle představa tě proto nikdy nezradí.

Část dotazuCo znamená
FROM students AS sVýchozí tabulka. s je alias – krátké jméno, kterým se na tabulku dál odkazujeme.
INNER JOIN classes AS cPřipoj tabulku tříd s aliasem c. Slovo INNER lze vynechat – samotné JOIN znamená totéž.
ON c.id = s.class_idPodmínka spojení. Téměř vždy: primární klíč jedné tabulky = cizí klíč druhé.
s.name AS studentObě tabulky mají sloupec name, proto musíme říct, čí name chceme, a výsledné sloupce přejmenovat.
Chyba, kterou uvidíš často: napíšeš-li jen SELECT name FROM students s JOIN classes c ON …, MySQL odpoví Column 'name' in field list is ambiguous – sloupec je nejednoznačný, existuje v obou tabulkách. Řešení: vždy piš alias.sloupec.
Pořadí v ON nehraje roli: ON c.id = s.class_id a ON s.class_id = c.id jsou totéž. U INNER JOIN nezáleží ani na pořadí tabulek – FROM classes c JOIN students s dá stejné řádky.
05 • LEFT A RIGHT JOIN

LEFT JOIN: všechny řádky zleva, i bez páru

LEFT JOIN ponechá každý řádek levé tabulky (té, která je v dotazu před slovem JOIN). Když k němu v pravé tabulce není pár, sloupce pravé tabulky se doplní hodnotou NULL.

SELECT s.name AS student,
       c.name AS trida
FROM students AS s          -- levá tabulka
LEFT JOIN classes AS c      -- pravá tabulka
       ON c.id = s.class_id
ORDER BY s.id;

V praxi se RIGHT JOIN skoro nepoužívá. Stejný výsledek dá LEFT JOIN s prohozenými tabulkami: FROM classes c LEFT JOIN students s ON …. Většina lidí píše jen LEFT JOIN a tabulku, ze které chce „všechno“, dává na začátek do FROM. Doporučujeme totéž.

Jak si zapamatovat, která tabulka je „levá“?

Přečti dotaz jako větu zleva doprava: „Vezmi žáky (levá) a připoj k nim třídy (pravá), pokud nějaké mají.“ LEFT JOIN tedy znamená: „levou tabulku chci celou, pravá je bonus“. Neplatí to podle toho, jak tabulky leží v diagramu, ale jen podle pořadí v dotazu.

07 • VÍCE TABULEK
Spojujeme tři i čtyři tabulky


JOINy se řetězí. Každý další JOIN … ON … připojí k dosavadnímu výsledku další tabulku. Postupuj po vazbách v ER diagramu.




1
Které tabulky potřebuji?
Chci jméno žáka, předmět a známku → students, subjects, grades.


2
Jak spolu souvisí?
Najdi v diagramu cestu: grades.student_id → students.id a grades.subject_id → subjects.id. Každá šipka = jedna podmínka ON.


3
Chci i řádky bez páru?
Ne → INNER JOIN. Ano → LEFT JOIN (a tabulku, ze které chci vše, dej do FROM).






SELECT s.name   AS student,
       sub.code AS predmet,
       g.grade  AS znamka
FROM grades AS g
JOIN students AS s   ON s.id   = g.student_id
JOIN subjects AS sub ON sub.id = g.subject_id
ORDER BY g.id;

Když JOIN „namnoží“ řádky


U vazby 1:N se řádek ze strany „1“ zopakuje tolikrát, kolik má partnerů na straně „N“. To je správně a očekávané – ale musíš na to myslet, když pak počítáš souhrny (předchozí kapitola).




SELECT c.name AS trida, s.name AS student,
       g.id, g.grade
FROM classes AS c
LEFT JOIN students AS s ON s.class_id  = c.id
LEFT JOIN grades   AS g ON g.student_id = s.id

09 • HLEDÁNÍ CHYBĚJÍCÍCH
Kdo nemá žádnou známku?


Častý úkol: najdi řádky, ke kterým neexistuje pár. Trik: udělej LEFT JOIN a ponech jen řádky, kde se pravá strana doplnila hodnotou NULL.




SELECT s.name AS student
FROM students AS s
LEFT JOIN grades AS g ON g.student_id = s.id
WHERE g.id IS NULL;


Výsledek


student
Černá








1
LEFT JOIN
Každý žák ve výsledku zůstane. Kdo nemá známku, má ve sloupcích g.* hodnotu NULL.


2
WHERE g.id IS NULL
Ponech jen řádky, kde se pár nenašel. Testujeme primární klíč pravé tabulky – ten u existujícího řádku nikdy NULL není.




Pozor: WHERE g.id = NULL nefunguje (vrátí 0 řádků). S NULL se vždy porovnává pomocí IS NULL / IS NOT NULL.






Totéž lze zapsat poddotazem: WHERE NOT EXISTS (SELECT 1 FROM grades g WHERE g.student_id = s.id). Poddotazům se budeme věnovat samostatně.

11 • DALŠÍ MOŽNOSTI
Self join, FULL JOIN, USING a další





Self join
Tabulka spojená sama se sebou


Kdo chodí do stejné třídy? Tabulku použijeme dvakrát pod různými aliasy.


SELECT a.name AS zak_1,
       b.name AS zak_2
FROM students AS a
JOIN students AS b
  ON a.class_id = b.class_id
 AND a.id < b.id;


zak_1zak_2


NovákSvobodová
DvořákČerná


a.id < b.id vyřadí dvojice „sám se sebou“ a duplicitu Svobodová–Novák. Typické použití: zaměstnanec a jeho nadřízený v téže tabulce.





FULL OUTER JOIN
MySQL/MariaDB ho nemají


FULL JOIN = všechny řádky z obou stran. V MySQL i MariaDB ho poskládáme z LEFT a RIGHT JOIN a operátoru UNION.


SELECT s.name AS student, c.name AS trida
FROM students s LEFT JOIN classes c
  ON c.id = s.class_id
UNION
SELECT s.name, c.name
FROM students s RIGHT JOIN classes c
  ON c.id = s.class_id;

UNION odstraní řádky, které vrátily obě poloviny. Pořadí řádků bez ORDER BY není zaručeno.





USING
Zkratka pro stejně pojmenované sloupce


Pokud se spojovací sloupce jmenují v obou tabulkách stejně, lze místo ON a.x = b.x psát USING (x). Kdyby tabulka tříd měla klíč class_id:


FROM students s
JOIN classes c USING (class_id)


V našich tabulkách (id vs. class_id) USING použít nelze – proto píšeme ON, který funguje vždy.





NATURAL JOIN
Raději nepoužívat


Spojí tabulky automaticky podle všech sloupců se stejným jménem. U nás mají obě tabulky id i name, takže:


SELECT * FROM students NATURAL JOIN classes;
-- = ON s.id = c.id AND s.name = c.name
-- výsledek: 0 řádků


Nesmysl, a bez chybové hlášky. Navíc stačí do tabulky přidat sloupec a dotaz začne vracet něco jiného.






Starý zápis s čárkou: v některých materiálech uvidíš FROM students s, classes c WHERE c.id = s.class_id. Je to INNER JOIN zapsaný postaru. Funguje, ale snadno se zapomene podmínka (→ kartézský součin) a neumí LEFT JOIN. Piš raději JOIN … ON.

14 • SHRNUTÍ
Co si odnést




① Proč
Data jsou kvůli normalizaci v několika tabulkách. JOIN je skládá zpět podle klíčů.


② Jak
Každý s každým, pak jen dvojice splňující ON (obvykle PK = FK).


③ INNER JOIN
Jen řádky, které mají pár na obou stranách.


④ LEFT JOIN
Celá levá tabulka; chybějící pár se doplní NULL. RIGHT = zrcadlo.


⑤ Chybějící
LEFT JOIN … WHERE prava.id IS NULL


⑥ ON vs. WHERE
U LEFT JOIN podmínky na pravou tabulku do ON, jinak se z něj stane INNER.


⑦ Násobení
Vazba 1:N opakuje řádky. Pozor na COUNT a SUM; nepřipojuj zbytečné tabulky.


⑧ MySQL/MariaDB
Nemají FULL JOIN (→ LEFT + RIGHT + UNION). JOIN bez ON = kartézský součin.






Tři otázky před každým JOINem:


1. Které tabulky potřebuji? 2. Jakými klíči spolu souvisí? 3. Chci vidět i řádky, které pár nemají? – Odpověď na třetí otázku rozhoduje mezi INNER a LEFT.
