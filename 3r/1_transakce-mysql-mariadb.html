Transakce: když musí proběhnout všechno, nebo nic.

Transakce spojí několik operací nad databází do jednoho logického celku. Když vše proběhne správně, změny potvrdíme. Když nastane problém, změny vrátíme zpět.

START TRANSACTIONCOMMITROLLBACKACID
Základní myšlenka: převod 1 000 Kč není „odečti peníze a potom možná přičti“. Je to jedna operace, která musí skončit v konzistentním stavu.
01 • PŘÍKLAD

Bankovní převod jako transakce

Představ si převod 1 000 Kč z účtu A na účet B. Databáze musí změnit minimálně dva záznamy.

Krok A

Odečtení z účtu A

balance = balance - 1000

Tato změna sama o sobě ještě nemusí být konečným stavem.

Krok B

Přičtení na účet B

balance = balance + 1000

Obě změny patří k jednomu převodu.

Co když po kroku A vypadne server?

Bez transakce může vzniknout nekonzistentní stav: peníze zmizí z účtu A, ale na B se nepřipíšou. S transakcí lze neúspěšnou operaci vrátit zpět.

02 • SMYSL

Proč transakce potřebujeme?

🔗

Více operací = jeden celek

Transakce spojí několik SQL příkazů do jedné logické operace.

🛡️

Konzistence

Databáze nemá zůstat „napůl změněná“, pokud část operace selže.

↩️

Možnost návratu

Pomocí ROLLBACK lze neuložené změny transakce zrušit.

Důležité: transakce není totéž co jeden SQL příkaz. Je to hranice atomické operace, která může obsahovat více příkazů.
03 • VLASTNOSTI

ACID: čtyři vlastnosti transakcí

A

Atomicity • Atomita

Transakce se provede jako celek, nebo se její změny zruší.

C

Consistency • Konzistence

Po úspěšném dokončení jsou data v souladu s definovanými pravidly databáze.

I

Isolation • Izolace

Souběžné transakce se navzájem ovlivňují podle nastavené úrovně izolace.

D

Durability • Trvalost

Po COMMIT databáze považuje změny za potvrzené a DBMS je chrání před běžným výpadkem.

Pomůcka: All or nothing • Correct state • Independent work • Don't lose committed data.
04 • SQL

Jak vytvořit transakci v MySQL / MariaDB?

Nejčastěji explicitně vymezíme začátek transakce, provedeme změny a nakonec použijeme COMMIT nebo ROLLBACK.

START TRANSACTION; UPDATE accounts SET balance = balance - 1000 WHERE id = 1; UPDATE accounts SET balance = balance + 1000 WHERE id = 2; COMMIT;

COMMIT

Potvrdí změny aktuální transakce. Po potvrzení jsou změny trvalou součástí databázového stavu.

Použijeme, když všechny kroky dopadly správně.

ROLLBACK

Zruší změny provedené od začátku transakce nebo od posledního relevantního bodu transakce.

Použijeme při chybě nebo když operaci nechceme potvrdit.

Alternativa: BEGIN se v MySQL/MariaDB používá jako synonymní způsob zahájení transakce. Často se setkáš s START TRANSACTION.
05 • ŽIVOTNÍ CYKLUS

Transakce krok za krokem

1

START TRANSACTION

Začíná transakční kontext. Následující změny mohou být potvrzeny nebo vráceny.

2

SQL operace

Provedeme jeden nebo více INSERT, UPDATE nebo DELETE.

3

Kontrola výsledku

Aplikace nebo DBMS zjistí, zda všechny požadované kroky proběhly správně.

4

COMMIT / ROLLBACK

Úspěch → COMMIT. Chyba → ROLLBACK.

06 • BACKEND

Transakce v PHP: DBMS ji řídí, aplikace rozhoduje

Na backendu obvykle použijeme PDO. Aplikace otevře transakci, provede databázové operace a podle výsledku ji potvrdí nebo vrátí.

$pdo->beginTransaction(); try { $stmt = $pdo->prepare( 'UPDATE accounts SET balance = balance - ? WHERE id = ?' ); $stmt->execute([1000, 1]); $stmt = $pdo->prepare( 'UPDATE accounts SET balance = balance + ? WHERE id = ?' ); $stmt->execute([1000, 2]); $pdo->commit(); } catch (Throwable $e) { $pdo->rollBack(); throw $e; }

beginTransaction()

PDO požádá databázové připojení o zahájení transakce.

commit()

Potvrdí všechny změny provedené v dané transakci.

rollBack()

Při chybě zruší dosud nepotvrzené změny transakce.

Pravidlo backendu: COMMIT až po úspěšném dokončení všech kroků. Při výjimce se snažíme provést ROLLBACK.
07 • SOUBĚŽNOST

Co když pracuje více uživatelů současně?

Transakce neřeší jen „chybu v programu“. DBMS musí koordinovat také souběžné transakce.

Izolace

Jedna transakce nemusí okamžitě vidět všechny necommitnuté změny jiné transakce. Konkrétní chování určuje isolation level.

Locky a souběh

DBMS může při práci s daty používat zámky a další mechanismy řízení souběhu, aby zachoval požadovanou konzistenci.

Pro maturitu / základ: stačí si spojit transakce s pojmy atomita, konzistence, izolace, trvalost a s příkazy START TRANSACTION, COMMIT, ROLLBACK.
08 • POZOR

Časté chyby a důležité nuance

Ne každý SQL příkaz se chová stejně

Transakční chování závisí mimo jiné na použitém storage enginu. U běžného InnoDB je transakční zpracování standardní součástí práce s daty.

COMMIT není jen „uložit formulář“

COMMIT potvrzuje změny celé aktuální transakce na daném připojení.

Autocommit

MySQL/MariaDB běžně pracují s autocommit. Pokud je zapnutý, samostatný příkaz může být automaticky potvrzen, pokud explicitně nevytvoříme transakci.

Transakce musí mít rozumný rozsah

Dlouhé transakce mohou držet zdroje a zámky déle, než je žádoucí. Backend by měl transakci zahájit co nejblíže potřebným operacím a rychle ji ukončit.

09 • SHRNUTÍ

Co si odnést

① Transakce

Je logický celek databázových operací, který má být proveden konzistentně.

② Atomita

Myšlenka všechno, nebo nic.

③ COMMIT

Potvrdí změny transakce.

④ ROLLBACK

Vrátí nepotvrzené změny transakce.

⑤ SQL

START TRANSACTION → SQL → COMMIT / ROLLBACK

⑥ PHP

beginTransaction() → try → commit(); při chybě rollBack().

Jedna věta na závěr:

Transakce chrání databázi před tím, aby složitější operace skončily pouze „napůl“.
